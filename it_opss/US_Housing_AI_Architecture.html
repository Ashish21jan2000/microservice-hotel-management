US Housing Board — Secure Agentic AI Platform (Text-to-SQL + Document RAG) Multi-department data (Finance, HR, Superadmin, ...) · 100+ cross-linked tables · S3 documents (PDF, images, Office)

New to this? Start here

Think of this system as a smart, very careful office assistant. A staff member asks a question in plain English, like "How much did we pay in housing grants last month?". Before the assistant does anything, a security guard checks who is asking (login and role). A rule book (RBAC) decides which data that person may see. A filter (guardrails) blocks bad or tricky questions. The assistant (the AI agent) then decides whether to look in the database (SQL) or read documents (PDFs and images in S3), or both. Every call to the AI model goes through one controlled door (the AI Gateway). Every step is recorded on CCTV (observability and audit).

Layer Details

Identity, RBAC & ABAC

  • SSO via Okta / Entra ID (OIDC + MFA); JWT carries dept, role, clearance, region
  • Central policy engine (OPA / AWS Verified Permissions – Cedar)
  • Roles: Superadmin, Finance-Analyst, HR-Manager, Auditor, Citizen-Service…
  • Row-Level Security & column masking in DB (e.g., SSN, salary)
  • Document ACLs copied into vector metadata → filtered retrieval
  • Agent runs on-behalf-of user: short-lived STS creds, no shared superuser

AI Gateway

  • Single egress to LLMs (Bedrock / Azure OpenAI / self-hosted)
  • Rate limits & token quotas per dept/user, cost chargeback
  • Model routing & fallback, semantic cache
  • Prompt/response logging with PII redaction
  • Secrets never exposed to clients (Secrets Manager / KMS)

Guardrails (input + output)

  • Input: prompt-injection & jailbreak detection, topic allow-list, PII detection
  • Indirect injection scan on retrieved document chunks
  • SQL guard: AST parse, SELECT-only, table allow-list per role, LIMIT, no DDL/DML, cost/timeout cap
  • Output: PII/PHI masking, toxicity, hallucination / groundedness check, citation enforcement
  • Human-in-the-loop for sensitive actions or bulk exports

Agentic Orchestrator

  • LangGraph / Bedrock Agents: Planner → Router → Tools → Synthesizer
  • SQL Agent: semantic layer + data catalog (Glue) with cross-dept join graph, few-shot examples, self-correction loop
  • Doc RAG Agent: hybrid search (BM25 + vector), reranker, citations
  • Hybrid: combine structured result + doc evidence
  • Conversation memory scoped per user (encrypted, TTL)

Data Plane

  • Dept DBs (RDS/Aurora) stay owned by dept; read replicas for AI
  • Federated query (Athena / Trino) or curated lakehouse for cross-dept joins
  • S3 per dept, SSE-KMS per dept key, Block Public Access, VPC endpoints
  • Ingestion: S3 event → Textract / OCR / image captioning → chunk → embed → OpenSearch (with ACL metadata)
  • Macie for PII discovery & classification tags

Observability & Governance

  • OpenTelemetry traces across every agent step (Langfuse / Arize / CloudWatch)
  • Metrics: latency, token cost, SQL success rate, retrieval hit rate, guardrail blocks
  • Immutable audit log (who asked what, which tables/docs accessed) → S3 Object Lock
  • SIEM integration (Security Hub / Splunk), anomaly alerts
  • Offline evals & red-teaming; model/prompt version registry
